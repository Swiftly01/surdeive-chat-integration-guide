Sur Drive · Ride chat and call tester

Two users, one ride. Chat over /chat, voice over /call.
What to try
  • Paste the rider's access token in the left panel and the driver's in the right, then connect both.
  • Open chat on a ride still searching → RIDE_CHAT_NOT_MATCHED.
  • Assign a driver, open chat, send messages both ways. Each message should arrive once.
  • Call from either side. Answer on the other, and watch the audio meter move.
  • Press Video call: the other side sees “is video calling”, with Answer (camera + mic) or Answer without camera. No camera? Tick test video pattern and each side sends a moving pattern with a live clock, so you can see frames arriving.
  • During a video call try Camera off. The other side just gets a black frame (the server has no event for it). A voice call never shows the video area.
  • Complete the ride: chat stays open for the post-ride window, calls give RIDE_CALL_NOT_ACTIVE.
  • Cancel the ride: chat gives RIDE_CHAT_RIDE_CANCELLED. History still loads.
  • Use a third user's token on this ride → 404 / RIDE_CHAT_NOT_PARTICIPANT.
  • Attach file sends a photo or document, and Record voice note sends audio. The message box becomes the caption. The page does not pre-check files, so the server's rules are what you see.
  • Use the Negative tests buttons: a fake image → ATTACHMENT_CONTENT_MISMATCH, an SVG → ATTACHMENT_TYPE_NOT_ALLOWED, 11 MB → ATTACHMENT_TOO_LARGE.
  • Close the driver's tab, send a message: the server should send a push (check server logs).
  • REST calls need CORS. Opening this file directly sends origin null; if requests fail, add it to CORS_ALLOWED_ORIGINS or serve the page over http.
